# GlobExplore production improvement pass

## Goal

Make the first deployed laboratory substantially more informative and visually legible without adding backend complexity or compromising the rigid-Earth model.

## Improvements to implement

### 1. Axis Lens becomes an explanatory instrument

- Add explicit visual magnification modes: `1×`, `10⁶×`, `10⁹×`, and `AUTO`.
- Keep numerical values physically exact and label all visual exaggeration.
- Draw both the figure-pole and instantaneous spin-vector pole.
- Show metric rings with scale labels and a directional azimuth guide.
- Add a one-line explanation of why microscopic shifts can be scientifically real but invisible at globe scale.

### 2. Add scale/context comparisons

- Add a compact `Scale context` rail showing the current pole shift against human hair width (~70 µm), a millimetre, a centimetre, and a metre.
- Add a latitude-response indicator showing that a point load has essentially zero first-order figure-axis tilt at the equator and pole and peaks near 45° latitude.
- Add an explicit `visual-only` tag to exaggerated axis geometry.

### 3. Improve globe spatial readability

- Add longitude meridians to the latitude grid.
- Add an atmospheric rim/halo and subtle polar emphasis.
- Add a geodesic source→destination transfer arc in `Move mass` mode.
- Render source and destination with clearly different semantics.
- Add a tiny north marker and equator label without turning the globe into a conventional map UI.

### 4. Improve scenario communication

- Make model-quality badges more prominent.
- Show scenario-specific explanatory text without opening the model drawer.
- Correctly distinguish published benchmarks from values generated by the simplified surface model.
- Preserve direct editing: selecting a preset configures the experiment, then any click or slider change becomes `Custom experiment`.

### 5. Mobile hardening

- Ensure Axis Lens can fill the inspection region on narrow screens without obscuring controls.
- Keep primary numeric result visible above the bottom control dock.
- Avoid overlapping the lens trigger, result panel, and bottom controls at 393×852 and 375×667.
- Reduce WebGL DPR on small devices while retaining smooth interaction.

## Exit criteria

The improvement pass is complete only when:

1. `npm run build` succeeds on Vercel with type checking.
2. Production deployment is `READY` and `/` returns HTTP 200.
3. Vercel runtime error aggregation reports no application errors after production requests.
4. Asia preset reports a non-zero sub-millimetre pole displacement rather than collapsing to zero numerically.
5. Changing latitude visibly changes the computed figure-axis response, with near-zero response at 0°/90° and a maximum near 45° for the point-mass thought experiment.
6. Axis Lens visibly distinguishes geographic pole, figure pole, and spin-vector pole.
7. Every lens magnification state labels the visual scale; numeric values do not change when magnification changes.
8. Move-mass mode shows both source and destination plus a transfer path.
9. Desktop UI has no overlap among scenario rail, metrics, Axis Lens, and control dock at 1440×900.
10. Mobile layout has no critical controls outside the visual viewport at 393×852 and 375×667 based on responsive CSS bounds.
11. Reduced-motion preference suppresses nonessential ambient motion where feasible.
12. Final production source commit on `main` matches the latest `READY` deployment.
